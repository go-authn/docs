authnd
check

ユーザーがログインに使うものを再起動する前の check

authnd check が何を開き、設定が提供される前に何を表示するか、その読み方、そして check には見えない唯一の失敗。

authnd check /etc/authnd
authnd check --config a.hcl --config b.hcl

check は設定をサーバーとまったく同じように読み込み、待ち受けを始める前にサーバーが開くものをすべて開きます。ファイル、データベース、この背後にあるディレクトリ、ID プロバイダーのディスカバリードキュメント、TLS 証明書と鍵、キータブです。そして、何が誰に向けて公開されるかを、待ち受けることなく表示します。すべての認証情報について出どころは表示しますが、中身は決して表示しません。終了コード 0 で、this configuration can be served で終わるか、終了コード 1 で、サーバーを止める一文を出力します。

提供できる設定

二つの user ブロック、一つの reader、一つの SQLite データベースを、二つのファイル(authnd.hcl と people.hcl) を含むディレクトリで構成した例です。

$ authnd check etc/authnd
ldap://127.0.0.1:3893, base dc=example,dc=org

USER   FROM                    CAN PROVE   PUBLISHED AS        WITH
alice  the configuration file  a password  account, uidObject  uid
bob    the configuration file  an NT hash  account, uidObject  uid
dora   a sqlite database       a password  account, uidObject  uid
eli    a sqlite database       an NT hash  account, uidObject  uid

GROUP      MEMBERS              PUBLISHED AS
engineers  dora and eli         groupOfNames
staff      alice, bob and dora  groupOfNames

alice has no uidNumber, gidNumber or homeDirectory: not a posixAccount, published as account, uidObject
bob has no uidNumber, gidNumber or homeDirectory: not a posixAccount, published as account, uidObject
dora has no uidNumber, gidNumber or homeDirectory: not a posixAccount, published as account, uidObject
eli has no uidNumber, gidNumber or homeDirectory: not a posixAccount, published as account, uidObject
group engineers has no gidNumber: not a posixGroup, published as a groupOfNames (member DNs, no memberUid)
group staff has no gidNumber: not a posixGroup, published as a groupOfNames (member DNs, no memberUid)

a bind carries a password
bob and eli cannot bind with a password: their sources hold only what an SMB server needs (an NT hash), which a bind cannot be checked against
cn=reader,dc=example,dc=org may search; every other bound client may not
sambaNTPassword is not published, so nothing here can authenticate an SMB session (NTLMv2 needs the password or its MD4, and a bind cannot answer it)

this configuration can be served

読み方

最初の行は、スキーム、アドレス、ベースです。ldap://、ldaps://、ldap+starttls:// のいずれかで、TLSを参照してください。

列
FROMその名前を所有するソース: the configuration file、a sqlite database (または postgres、mysql)、またはこの背後にあるディレクトリの URL
CAN PROVEa password (保持しているので比較でき、そこから鍵を導出できる)、a password check (別のディレクトリが可否を答える)、an NT hash、N keys、a one-time-code secret、または nothing
PUBLISHED AStop を除いたエントリのオブジェクトクラス。各形態が示すとおりです。スキーマに適合しないエントリの場合は NOT PUBLISHED (see below)
WITHエントリが持つ属性。検索が返すエントリから読み取ったもの: uid、クラスが許す場合の cn、ソースが与えたもの (破棄されたものを除く)、鍵がある場合の sshPublicKey、publish_nt_hash が有効で、その人が NT 鍵と SID を持つ場合の sambaSID と sambaNTPassword

グループの表にも PUBLISHED AS 列があり、posixGroup、groupOfNames、organizationalRole のいずれかです。v0.10.2 までは、PUBLISHED AS は属性のリストで、ほぼ全員が uid and cn であり、WITH 列はありませんでした。

表の後の行は、設定に頼る前に知っておくべきことを伝えます。まず、エントリについて。

  • posixAccount ではない人と、uidNumber、gidNumber、homeDirectory のうち足りないもの
  • gidNumber のないグループと、代わりに何として公開されるか
  • 破棄されたすべての属性。そのエントリのどのクラスもそれを許さないためで、どのクラスなら許すか
  • 公開されないすべてのエントリと、スキーマ検証で見つかったそれぞれの問題
  • NT 鍵を持つが sambaSID がない人。したがって sambaNTPassword もない

v0.12.0 からは、最初の行と表の間に、サイトスキーマが追加したものと、ソースが宣言するものが表示されます。

  • 読み込まれたスキーマファイルと schema ブロックと、それぞれが追加するもの:schema: etc/authnd/example.schema adds 3 object identifier macros, 2 attribute types and 2 object classes
  • 各ソースが宣言するクラス: users "sql" declares exampleStaff and exampleLockerHolder for its people。宣言の位置も付く
  • 人またはグループから外されたすべてのクラス。そのソースが宣言するクラスの MUST が足りないためで、ben is published without exampleStaff, which its source declares: ben has no exampleEmployeeId, which exampleStaff requires、そして属性の行の後に、それと一緒に外れたものが続く
  • 二つのソースが異なるクラスを宣言するグループ: 最初のソースの一覧が公開され、二つ目のものは無視される

ビルドできないファイル、再定義、そして宣言されたクラスが未定義、STRUCTURAL、またはauthnd が自ら導出するものである場合は、check もサーバーも停止し、ファイルまたは設定の位置が示されます。

次に、バインドと検索について。

  • バインドが運ぶもの: a password、mfa ブロックがある場合はa password with a 6-digit code after it、oidc ブロックがある場合はトークンの出どころとその経路
  • パスワードではまったくバインドできない人: NT ハッシュしか知られていない人。人々を参照
  • 検索できる人: reader、または no reader is declared: nothing may search, and binds are not affected
  • sambaNTPassword が公開されるかどうかと、その経路。publish_nt_hashを参照
  • kerberos ブロックがある場合は、レルムとチケットを発行できる人とできない人、その理由
  • mfa ブロックがある場合は、第二要素のない人、したがってパスワードでバインドできない人。横に oidc ブロックがある場合、その行には、amr が二種類を示すトークンならそれでも通るという注記が加わります
  • どのソースにもいない人を名指しするグループ

最後のものはそのまま公開されます。ある一つのシステムの窓口が、別のシステムが所有する名前を正当に持つことがあるためです。ただし知らされます。もう一つの解釈は誤字だからです。posixGroup では、その見知らぬ人は memberUid です。groupOfNames では、ここにあるどのエントリも指さない member DN で、ここでは member: uid=zoe,ou=people,dc=example,dc=org がそれにあたり、go-authn/directory の ldapdir は v0.14.0 からこれを誰にも対応付けません。ここではデータベースの team_members テーブルに zoe の行があり、zoe はここでは誰でもありません。

GROUP      MEMBERS              PUBLISHED AS
engineers  dora, eli and zoe    groupOfNames
staff      alice, bob and dora  groupOfNames
[...]
engineers names zoe, who has no entry here: the group is published as it stands, and nothing here can prove them

(見知らぬ人を名指しする group ブロックは、完全に拒否されます。人々を参照してください。)

拒否されるもの

以下のいずれも、check とサーバーの両方を、終了ステータス 1 で止めます。それぞれ関連するページで説明しています。いくつかを出力のまま示します。

$ authnd check cases/nobody.hcl
authnd: there is nobody here: name a user, or a users block reading a database or a directory

$ authnd check cases/nthash-clear.hcl
authnd: publish_nt_hash needs cert_file and key_file: an NT hash IS the credential, and 0.0.0.0:3893 is not loopback, so it would cross a network in the clear

$ authnd check cases/krb-mfa.hcl
authnd: kerberos and mfa together: the mfa block asks every bind for a password AND a code, and a kinit carries only the password -- this KDC has no second-factor pre-authentication, so a realm here would accept one factor where the mfa block demands two. Remove one of the blocks

$ authnd check empty
authnd: empty has no .hcl files in it

$ authnd
authnd: no configuration: give a .hcl file or a directory of them

証明書、キータブ、そして check に見えない唯一のこと

読み込めない証明書と、krbtgt/REALM のないキータブは、サーバーが使うのと同じ言葉でcheck に拒否されます。

$ authnd check cases/badcert
authnd: the certificate: open tls/missing.pem: no such file or directory

$ authnd check cases/nokrbtgt
authnd: kdc: the keytab has no krbtgt key for this realm: matching key not found in keytab. Looking for "krbtgt/EXAMPLE.ORG" realm: EXAMPLE.ORG kvno: 0 etype: 18

待ち受けなしには check が知り得ないのは、ポートが空いているかどうかです。同じ Kerberosアドレスで動く二つ目のサーバーは check を通り、起動時に拒否されます。

$ authnd --config cases/realm2
authnd: kerberos udp 127.0.0.1:18388: listen udp 127.0.0.1:18388: bind: address already in use

サービスアカウントとして実行する 

sudo -u authnd authnd check /etc/authnd

root しか読めないファイルが、再起動時ではなくここで失敗するようにするためです。アップグレードの前に、新しいバイナリで実行してください。インストールを参照してください。
