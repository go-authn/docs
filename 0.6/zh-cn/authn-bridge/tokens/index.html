authn-bridge
令牌

令牌、密码和密钥

应用程序从 authn-bridge 得到什么：ID 令牌和访问令牌、设备授权、用于 SMB 和 S3 的应用密码，以及 WireGuard 密钥。

这里的每种凭据都始于在人员所属机构的同一次登录。不同之处在于凭据是为谁而设，以及如何收回。证书见它们自己的页面。

授权码流程，每个客户端都必须使用 PKCE S256。没有code_challenge_method 的请求会被拒绝，而不是被当作 S256 处理，因为 RFC 7636 将 plain 定为默认值。配置了pkce = "or_nonce" 的机密客户端可以改为发送 OpenID nonce。

ID 令牌

它面向客户端，关于登录而不是关于人员：RS256，aud 为客户端ID，sub、auth_time、at_hash，请求带有 nonce 时的 nonce，以及IdP 说明其所用认证上下文时的 acr。有效期为id_token_lifetime，默认五分钟。

其中没有任何关于人员的内容。 scope 所释放的声明位于/userinfo，这正是 OIDC Core 5.4 在签发访问令牌时的规定，而访问令牌总会签发。ID 令牌本身就是凭据的客户端（例如 opkssh）设置 id_token_claims = true，以便把它们复制进去。ID 令牌只会为带有 openid scope 的请求签发。

访问令牌

面向客户端 audience 中的资源服务器，如 RFC 9068 所述：用 signing_key_file（RS256）或 access_token_key_file（ES256）签名，typ: at+jwt，有效期为 token_lifetime（默认一小时）。它携带资源服务器无需询问任何人即可作出决定所需的内容：preferred_username、groups、idp（为之担保的 IdP 的实体 ID）、scope、client_id，以及 IdP 说明其会话何时结束时的 session_end。组可以按客户端省略：见下文。

audience 指名多个资源服务器的客户端，可以用 RFC 8707 的 resource 请求发往其中一个的令牌：参见多个资源服务器。

它省略了什么，以及原因

没有 auth_time，也没有 acr，尽管 RFC 9068 允许两者。它们仍保留在ID 令牌中，OIDC Core 把它们放在那里。没有任何程序从访问令牌中读取它们：不是本提供方（它按 jti 查找令牌），也不是go-fileshare。然而，访问令牌也会被粘贴为 SSH keyboard-interactive 的答案（ssh-oidc 的 mccli，由 motley-cue 在/userinfo 检查），而 OpenSSH 只读取其中的 1023 个字符；仅 IdP 的 acr，urn:oasis:names:tc:SAML:2.0:ac:classes:PasswordProtectedTransport，就占大约 90 个。在 v0.22.0 之前，访问令牌同时携带两者。

ES256 访问令牌（access_token_key_file）在长 eppn 和三个 AARC entitlement情况下的长度，由 authn-bridge 的 TestES256AccessTokens 测量，使用真实长度的签发方，并对照 RENATER 元数据的 shibmd:Scope 长度（743 个 scope）：

scope 长度字符数
13中位数885
22第 95 百分位945
29第 99 百分位992
44最长1092：超出

在 v0.22.0 之前，同一个令牌为 1014 / 1074 / 1121 / 1221 个字符：从第 95 百分位起就超出了。仍然放不下的是最长的 scope，尤其是许多组：每个 entitlement 都会加上其完整的 URN，而且没有任何东西限制 IdP 发送多少个。用 3072 位密钥签名的 RS256 访问令牌，在没有任何组的情况下就有大约 1150 个字符，因此用于 SSH 的令牌使用 ES256 签名。超过 1023 个字符时，mccli 会改为向 motley-cue 索要一次性密码，motley-cue 默认允许这样做；粘贴到普通ssh 中的令牌则必须放得下。

对提出要求的客户端不含组（v0.23.0）。每个组都会加上其完整的URN，而且没有任何东西限制 IdP 发送多少个，因此没有任何密钥和任何签名算法能够确保携带组的令牌一定放得下。access_token_groups = false 的客户端得到的访问令牌不含人员的 groups：

client "oidc-agent" {
  device              = true
  audience            = ["ssh"]
  access_token_groups = false
}

它面向 ssh-oidc：oidc-agent 获取令牌，mccli 将其作为keyboard-interactive 的答案粘贴，而 motley-cue 在 /userinfo 检查它并在那里读取组。由 authn-bridge 的 TestAccessTokenWithoutGroups 测量，对于属于 50 个组的人员，在最长的 RENATER scope（44）和真实长度的签发方情况下，ES256 令牌为 732 个字符。

针对测试联邦，一个属于三个组的人员通过该客户端用设备授权登录：

默认值仍为 true。 go-fileshare 与任何仅凭令牌作出决定的资源服务器一样，需要令牌中带有组：只有在令牌发往读取 /userinfo 的服务器的客户端上，才省略它们。

与证书并用时被拒绝。 SSH 和 X.509 证书从访问令牌中获取人员的组，因此带有 access_token_groups = false 以及 ssh_certificates 或 x509_certificates 的客户端，会签发不含任何组的证书，而按组授权的服务器会拒绝该人员，却没有任何地方说明原因。check 与服务器在启动时一样，会拒绝这种组合：

client "oidc-agent" {
  device              = true
  audience            = ["ssh"]
  access_token_groups = false
  ssh_certificates    = true
}
$ authn-bridge check --config etc/bridge.hcl
authn-bridge: client "oidc-agent": access_token_groups = false with ssh_certificates or x509_certificates: the certificates take the groups from the access token, and would carry none -- use one client for the certificates and another for tokens pasted into ssh
$ echo $?
1

请为证书使用一个客户端，为粘贴到 ssh 中的令牌使用另一个客户端。

带有提供方自身 scope（ssh、nfs、app_password、wireguard、wireguard_peers）之一的令牌只发往提供方：其 aud 是签发方，这些端点会拒绝其他任何令牌。资源服务器收到的令牌无法在此重放：

$ curl -s -X POST http://127.0.0.1:28473/ssh/certificate -d x -D - -o -

the token is not valid

已经发放的访问令牌是资源服务器自行检查的签名声明。RevokePerson终止的是带着它回到这里的一切；资源服务器通过Shared Signals得知。

轮换令牌签名密钥

每个依赖方都用 /jwks 发布的密钥验证令牌。就地更换密钥会使它们手中的所有令牌失效，而在它们取得之前就开始使用的密钥会被拒绝。retired_signing_key_files 让这两种情况都变得安全：列在其中的密钥只发布，从不签名。轮换需要两次重启，因为提供方不会重新加载配置，SIGHUP 也会被忽略。本节依据 bridge 的 pull request #80（2026-10-26 合并，晚于标签 v0.23.4）之后的 README。

  1. 生成下一把密钥，放在当前密钥旁边。该命令拒绝覆盖已有文件：

    authn-bridge keygen --key /var/lib/authn-bridge/oidc-2026-10.key

  2. 在它开始签名之前先发布。 把它加入 retired_signing_key_files，保持 signing_key_file 不变，运行 authn-bridge check，然后重启：

    signing_key_file          = "/var/lib/authn-bridge/oidc-2026-04.key"   # still signing
retired_signing_key_files = ["/var/lib/authn-bridge/oidc-2026-10.key"] # published only

    /jwks 现在列出两个 kid，而新令牌仍带旧的 kid。等待的时间至少要等于依赖方缓存密钥集的最长时间。遇到未知 kid 就重新获取的依赖方（go-authn/oidc 会这样做，每个 MinRefresh 至多一次）无需等待；按固定时间缓存的依赖方则需要等那么久。

  3. 切换。 把新密钥设为 signing_key_file，并把旧密钥移到 retired_signing_key_files。然后运行authn-bridge check 并重启：

    signing_key_file          = "/var/lib/authn-bridge/oidc-2026-10.key"
retired_signing_key_files = ["/var/lib/authn-bridge/oidc-2026-04.key"]

    /jwks 仍列出两个 kid，新令牌带新的 kid。用旧密钥签名的令牌继续可以验证。

  4. 淘汰旧密钥，要在它签名的令牌不可能再被出示之后：至少是 token_lifetime（默认 1 小时）与id_token_lifetime（5 分钟）中较长者，再加上依赖方的时钟偏差及其密钥集缓存。对 opkssh，则改为等待PK Token 的有效期（默认一天，最长一周）。然后把它从列表中移除并重启：/jwks 只列出一个 kid。

每一步都可以用 curl -s https://login.example.org/jwks 查看已发布的 kid；新令牌的 kid 是任一访问令牌或ID 令牌的第一段，经 base64url 解码得到。

access_token_key_file（ES256）以同样方式轮换：用 authn-bridge keygen --access-token-key 写出下一把，被淘汰的和其他密钥一样放入 retired_signing_key_files。没有 state 块时，每次重启都会让所有人退出登录，因为刷新令牌和 /userinfo 保存在内存中；已经签发的访问令牌在资源服务器上仍可验证。

README 报告说，这已用 llmflow-gateway 作为依赖方，在 go-llmflow/bench（e2e/oidc，TestBridge/c/key-rotation）中端到端验证：第 2 步之后，/jwks 列出两个 kid，而令牌仍带旧的；第 3 步之后，切换前签名的令牌和切换后签名的令牌都被接受，只获取了一次密钥集；切换后立即进行 SSO 登录也能正常工作。

没有浏览器：设备授权

WebDAV 客户端、脚本、终端都没有可以把人带到大学登录页的浏览器。带有 device = true 的客户端会索要代码（RFC 8628），人员在任何其他设备上登录：

client "rclone" {
  device           = true
  audience         = ["fileshare"]
  refresh_lifetime = "720h"     # refresh tokens, off unless set
  name             = "rclone (WebDAV)"
}

authn-bridge token --issuer https://login.example.org --client rclone 输出一个访问令牌，第一次时登录，之后则刷新；它使用的是golang.org/x/oauth2 的设备客户端，而不是这里编写的。

用户代码取自 BCDFGHJKLMNPQRSTVWXZ 的八个字母（没有元音，没有数字），有效期十分钟；在此期间每个主机（IPv4 地址、IPv6 /64）最多允许十个错误代码，其周围的 /24 或 /48 则允许十倍之多
轮询每五秒一次；轮询更快会得到 slow_down
等待中的设备最多 20,000 个；超过后最旧的会被挤出，而不是拒绝所有人
刷新令牌每次使用都会轮换，位于一个在登录时由 refresh_lifetime 固定其终点的族之中；已退役的令牌被再次使用会吊销该族及其所换取的访问令牌

应用密码

NTLMv2 和 SigV4 证明的是服务器必须已经持有的秘密，因此没有任何令牌适用于 SMB 或 S3。带有 app_passwords = true 的客户端允许带有app_password scope 的令牌设置一个，生成后只显示一次：authn-bridge app-password --issuer ... --client files（--remove 将其删除）。

app_passwords {
  driver   = "sqlite"          # sqlite, postgres or mysql
  dsn_file = "/etc/authn-bridge/apppw.dsn"
  store    = ["nt_hash"]       # the default, SMB only; add "password" for S3
  lifetime = "2160h"           # the default, 90 days
  # table  = "app_passwords"   # the default
}

该表在缺失时创建：login, password, nt_hash, expires, idp。只存储协议所需的内容：SMB 用的 NT 哈希，仅当 store 要求时才存储密码本身。go-fileshare 用 users "sql" 块读取它；请在其查询中写明列名，绝不要用 *。

禁用某人会移除其密码；禁用某机构会移除该机构所有人员的密码。被移除的密码在 go-fileshare 下次读取其目录时失效。

WireGuard 密钥

WireGuard 仅凭公钥认证对端，别无其他：没有证书，没有过期，没有吊销。因此提供方保存着对这把密钥是谁的，它是否仍可连接？ 的回答。设备的 VPN 客户端为一段租期注册公钥；私钥从不离开设备；网关读取有效密钥，其形式是仅为它签名的列表。

certificates_file = "/var/lib/authn-bridge/certificates.json"   # keys are recorded beside the certificates

wireguard {
  lifetime = "24h"              # the default: how long a key is listed; registering again renews it
  max_keys = 10                 # the default: devices per person
}

client "vpn" {                  # what people log in with
  device         = true
  wireguard_keys = true
}

client "vpn-gw" {               # the gateway's own client
  secret_file     = "/etc/authn-bridge/vpn-gw.secret"
  wireguard_peers = ["vpn"]     # the clients whose keys it reads
  ssf_receiver    = true        # optional: told at once when somebody is disabled
}
POST /wireguard/key{"public_key": "...", "device": "laptop"}，带有 wireguard scope 的令牌；答复租期的结束时间
DELETE /wireguard/key{"public_key": "..."}：所有者收回一把密钥
GET /wireguard/peers使用网关自己的 client_credentials 令牌，scope 为 wireguard_peers：一个类型为 wireguard-peers+jwt 的签名 JWT，发往该网关，有效期五分钟

别人持有的密钥、已被收回的密钥，以及超出数量上限的密钥，都会被以 409 拒绝。网关客户端必须是机密客户端，并且必须指名具有 wireguard_keys 的客户端。列表的格式以及网关一侧的内容属于 go-authn/wireguard。

OpenPubkey 与 opkssh

opkssh 把 ID 令牌变成 SSH 登录，完全不需要 CA，而它所生成的令牌（PK Token）比其中的 ID 令牌存活更久。提供方在授权码流程和设备流程中原样返回nonce，使用 RS256 签名，并且只要 retired_signing_key_files 指名了某把已退役的密钥，就会一直发布它，使轮换之前签名的PK Token 仍然可以验证：

retired_signing_key_files = ["/var/lib/authn-bridge/oidc-2026-03.key"]

请给 opkssh 一个专属的客户端并设置 id_token_claims = true：它根据 PK Token 的声明匹配人员，而它的 ID 令牌会传到它所登录的每台服务器。
