联邦一侧

authn-bridge 如何读取 SAML 联邦的元数据、固定其签名者、让每个 IdP 受其自身 scope 约束，并把断言转换为声明。

在这一侧，authn-bridge 是 SAML 服务提供方。它向联邦（RENATER 的 Fédération Éducation-Recherche，或 eduGAIN）注册一次，并且信任联邦的元数据：一份已签名的文档，列出每个成员 IdP、它们的签名密钥，以及各自可以为之担保的域。SAML代码是 go-authn/saml。

saml {
  key_file  = "/var/lib/authn-bridge/saml.key"   # RSA: IdPs encrypt assertions to it
  cert_file = "/var/lib/authn-bridge/saml.crt"

  metadata_url         = "https://pub.federation.renater.fr/metadata/fer/idps.xml"
  metadata_cert_file   = "/etc/authn-bridge/metadata-signature-2026.pem"
  metadata_fingerprint = "68:2F:20:58:41:9E:D0:79:EB:FE:3C:27:D6:A4:A4:09:39:6F:AE:3F:10:5F:22:EA:04:0F:04:F3:78:2D:5C:C0"

  discovery = "https://discovery.renater.fr/renater"   # or leave it out for this provider's own list
  # idps    = ["https://idp.univ-example.example/idp/shibboleth"]   # restrict; one entry skips the choice

  names             = { fr = "Passerelle OIDC", en = "OIDC gateway" }
  technical_contact = "admin@example.org"
}
键默认值
entity_id签发方 + /saml此服务提供方在联邦中的名称
key_file、cert_fileSP 的 RSA 密钥和证书
metadata_urlhttps://，由其他程序维护的副本用 file://，或仅限环回的 http://
metadata_cert_file、metadata_fingerprint联邦的签名证书及其 SHA-256 指纹，二者都是必需的
discovery本提供方自己的列表将人员引导至的外部发现服务
idps联邦的所有 IdP将登录限制在这些实体 ID 之内
names、descriptions、information_url、privacy_statement_url、technical_contact以签发方的主机作为名称写入 SP 元数据的内容

元数据的签名者被固定

为元数据签名的证书是此主机上的一个文件，而其 SHA-256指纹写在配置中。每次启动都会对照指纹检查该证书，因此磁盘上被替换的文件会被发现，而不是被信任：

authn-bridge: saml: fed/fed.crt is not the certificate with fingerprint 68:2F:20:58:41:9E:D0:79:EB:FE:3C:27:D6:A4:A4:09:39:6F:AE:3F:10:5F:22:EA:04:0F:04:F3:78:2D:5C:C0

与它所担保的文档通过同一渠道到达的密钥，什么也担保不了。因此指纹来自联邦的网页，绝不来自获取证书的那次下载：

openssl x509 -in /etc/authn-bridge/metadata-signature-2026.pem -noout -fingerprint -sha256

文档被拒绝的情形

  • 当它不是由该证书签名、使用 SHA-1 签名，或其签名覆盖的不是根元素之外的另一个元素时；

  • 当它没有 validUntil，或已超过该时间时。 这是 RENATER 自己的元数据，发布于 2026 年 9 月 29 日，在 10 月 10 日读取：

    $ authn-bridge check --config v/renater-expired.hcl
authn-bridge: the federation's metadata: metadata expired at 2026-10-08T07:30:02Z

    没有重新运行：该元数据已不再发布，这是 2026 年 10 月 10 日捕获的输出。

  • 当其 validUntil 距今超过 28 天时：有效期长达数年的文档会被重放攻击保持数年有效；

  • 当它比正在使用的文档更旧时（validUntil 更早）。它签名有效且尚未过期，因此没有其他机制会拒绝它，而它可能是含有此后已被吊销密钥的那一份，由路径上的任何人提供；

  • 通过普通 http 访问环回之外的任何地址时。签名可以发现更改，却发现不了扣留新文档并继续提供旧文档的代理。

刷新

元数据在提供方监听之前获取，然后在文档 cacheDuration 的四分之三处再次获取，间隔不短于五分钟、也不长于十二小时，并且每当管理 API 的 RefreshMetadata 要求时也会获取。刷新失败时保留上一份良好的副本，但只保留到其自身的validUntil。此后不再为任何内容担保，每个 IdP 都会消失，/readyz 会表明提供方尚未就绪。联邦服务器短暂无法访问不会使任何人退出登录；无法访问数日也不会让提供方继续信任过期的密钥。

在文档之内，IdP 只有在支持 SAML 2.0 并发布HTTP-Redirect SingleSignOnService 时才会保留。被描述了两次的实体会被整个丢弃，因为没有任何内容说明哪个描述才是正确的，而某个成员无法读取的证书只会使该成员被排除，而不是整个联邦。

每个 IdP 可以声明什么

联邦有数百个成员，否则其中任何一个都可以声称自己是alice@another-university.example。每个成员的元数据都列出其shibmd:Scope，即它可以为之担保的域；正则表达式 scope 会被忽略，而不是被遵从。

标识符。 位于断言方 IdP 的 scope 之外的带 scope 的值（subject-id、pairwise-id、eduPersonPrincipalName、eduPersonScopedAffiliation）会被丢弃，含有多个 @ 的值不属于任何 scope。

组。 当允许登录的 IdP 多于一个时，eduPersonEntitlement 或 isMemberOf 的值只有在其命名空间是该 IdP 的某个 scope或位于其下时才会保留：

值其命名空间
urn:mace:<domain>:...<domain>
urn:geant:<domain>:...（AARC-G002）<domain>
https://<host>/...<host>
其他任何值无：丢弃

组决定人员可以做什么，在每个资源服务器上、在每个证书中都是如此，因此无人能够确定归属的值不会被传递。为许多机构的人员断言组的社区代理，需要按实体 ID 明确指名，并给出它可以断言的前缀：

claims {
  trusted_groups = {
    "https://proxy.eduteams.org/saml2/idp/metadata.php" = ["urn:geant:eduteams.org:"]
  }
}

当 saml { idps } 中恰好只有一个 IdP 时，该 IdP 的每个值都受到信任。

从断言到声明 

claims {
  username = "eppn"            # preferred_username: eppn, subject_id, uid or mail
  groups   = ["entitlement"]   # groups: entitlement, scoped_affiliation, affiliation, is_member_of
}

uid 和 mail 不受任何 scope 约束，而 affiliation（staff、student）不指明任何机构。因此每一个都需要 saml { idps } 恰好列出一个IdP；有更多时，它们会在启动时被拒绝。

sub。 其背后的标识符按以下顺序取得：subject-id，然后pairwise-id，然后 eduPersonPrincipalName，然后 eduPersonTargetedID，然后是限定符为 IdP 自身的持久 NameID。它由IdP 的实体 ID 限定，而 sub 是在主体盐值之下对它计算的 HMAC-SHA256：稳定、不可逆，也不是地址。public 对每个客户端都相同，pairwise 则因客户端而异。不释放其中任何一项的 IdP 会被拒绝，因为无法两次识别出同一个人。邮件地址绝不是标识符，并且没有 email_verified：IdP 断言某个地址，并不等于有人验证过此人会读取该邮箱。

请求向 IdP 提出什么要求。 prompt=none 变为 IsPassive，没有会话的 IdP 会答复 login_required。prompt=login 和 max_age=0 变为 ForceAuthn；对于任何其他 max_age，如果其 IdP 认证该人员的时间比这更早，则该人员会被带着 ForceAuthn 送回。acr_values 变为RequestedAuthnContext，而以另一个上下文作答的 IdP 会被拒绝：要求第二因素的客户端绝不会在实际上没有得到时被告知已经得到。

什么会被拒绝

在 ACS 处，go-authn/saml 拒绝的一切：未签名或使用 SHA-1 的断言、多个断言、被重放的断言、位于外来 scope 中的标识符。然后是本提供方自己的拒绝：

  • 投递到另一个浏览器中的 IdP 响应：登录是通过其自身密封的 cookie 找到的，绝不是通过响应所携带的 RelayState；否则任何人都可以把自己的 IdP 响应发送到别人的浏览器，并以发送者的身份让那个人登录；
  • 配置不再允许的 IdP，或管理 API已将其禁用的 IdP；
  • 在此处被禁用的人员或机构，无论机构怎么说。

启动时，带有 IdP 列表同时又使用 RENATER 的发现服务的配置会被拒绝，因为该发现服务列出所有 IdP，无法被限制：

authn-bridge: saml: an external discovery service lists every IdP; with `idps` restricted, leave `discovery` out and this provider lists them itself
