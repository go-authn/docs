Status

Which releases these pages describe, what each release added, and what is not implemented yet.

These pages are documentation version 0.5, and describe:

programreleasemodule
authndv0.12.0github.com/go-authn/authnd
authn-bridgev0.23.3github.com/go-authn/bridge
authn-revokdv0.6.5github.com/go-authn/revocation
sshcert-authorizev0.1.7github.com/go-authn/sshcert

The libraries’ versions are on their own page;ldap is v0.9.0, with schemas in HCL2 and the ldapschema converter, and directory v0.15.0, with declared object classes. authnd v0.12.0 embeds ldap v0.9.0 and directory v0.15.0.A new minor version of any program above is a new documentation version, so the pages a reader finds under /docs/0.5/ keep describing what they installed; those of the previous releases stay under /docs/0.1/,/docs/0.2/, /docs/0.3/ and /docs/0.4/.

Security: use authnd v0.12.0, not v0.11.1

authnd verifies certificates (x509.Certificate.Verify, reached from main per govulncheck), and Go 1.27.2’s crypto/x509 did not distrust the compromised intermediate certificates that GO-2026-6809 names. v0.11.1’s release binaries were built with Go 1.27.2 and are affected. v0.12.0 is built with Go 1.27.3 and its go directive is 1.27.3, so go install switches to the fixed toolchain by itself; govulncheck under 1.27.3 reports no vulnerabilities. Its release binary reports go1.27.3 ingo version -m. See the upgrade note.

Security: take authn-bridge v0.23.3 and authn-revokd v0.6.5

Under Go 1.27.2, govulncheck reports GO-2026-6809 in both programs: crypto/x509’s Certificate.Verify did not reject known compromised intermediate certificates. It is fixed in Go 1.26.10 and 1.27.3. Release binaries built with an older Go are affected. v0.23.3 and v0.6.5 are built with Go 1.27.3 and their go directive is 1.27.3, so go install switches to the fixed toolchain by itself; their release binaries report go1.27.3 in go version -m. sshcert is not affected and has no new release.

What each release added

Each line is the change a release was cut for. Releases that only updated dependencies are left out, except those this documentation version describes.

authnd

v0.1.0an LDAP server for people who are somewhere else: a file, a SQL database, another directory
v0.2.0a second factor, over a protocol with one field
v0.5.0password changes that touch exactly one identity; a reload with no race; the KDC sees changes
v0.6.0the security fixes of oidc, directory, ldap, totp and mfa
v0.7.0the old password is required to change one; secrets are compared as fixed-length digests
v0.8.2a code counts only behind the right password; a reader is keyed by its configured DN
v0.9.0built and tested with Go 1.27.1, pinned rather than stable
v0.9.2release binaries, SHA256SUMS and build provenance on every tag
v0.9.3binaries built outside the checkout; each must report the tag exactly
v0.9.4a SIGHUP no longer ends authnd: it is logged, and nothing is reloaded
v0.9.5the release checks every binary’s build information, not one
v0.9.6check says why each person cannot be issued a ticket
v0.10.0check opens the certificate and the keytab, as the server does; it names who cannot bind with a password, and who a token still admits; the listening line comes after the realm opens
v0.10.1go-authn/kdc v0.4.2: a till of 19700101000000Z gets the longest ticket, not one expired in 1970
v0.10.2go-authn/directory v0.12.0: an empty group is published as a posixGroup without memberUid
v0.11.0standard-schema entries, each held to the schema served at cn=Subschema; attributes, users_attributes and groups_attributes; (uidNumber>=1000) compares integers. ⛔ publish_nt_hash needs a samba block, and a consumer filtering on posixAccount or posixGroup sees fewer entries
v0.11.1the startup line names only the sources somebody is served from: with no user block it no longer names the configuration file
v0.12.0site schemas: schema_files (OpenLDAP .schema and cn=config LDIF, as published; a redefinition is refused, even identical, as slapd does) and a schema { } block; auxiliary classes declared per source with object_classes, validated at startup and published with their superclasses; check reports the files, the declarations, the classes left off a person for a missing MUST, and groups two sources disagree on. ⛔ Built with Go 1.27.3: v0.11.1’s binaries (Go 1.27.2) are affected by GO-2026-6809

Not implemented yet

  • Writes through LDAP, beyond a person changing their own password. authnd answers a modify of one’s own userPassword and the RFC 3062 password modify operation (what ldappasswd sends), both only with the current password, and nothing else: add, delete and modifyDN exist in go-authn/ldap and are deliberately not wired (server.go). The library carries a modify as an ordered list (RFC 4511 4.6) and answers the read entry controls (RFC 4527), so the shape is there; what is missing is the policy of who may write what.
  • A second factor inside Kerberos: OTP pre-authentication (RFC 6560) in FAST (RFC 6113). Until it exists, a kerberos block and an mfa block cannot both be configured.
  • RC4-HMAC: the realm issues aes256-cts-hmac-sha1-96 only, so a person known only by an NT hash cannot be issued a ticket. This is a choice (RC4 is deprecated by RFC 8429), not a gap waiting to be filled.
