authn-bridge
フェデレーション側

フェデレーション側

authn-bridge が SAML フェデレーションのメタデータを読み、その署名者を固定し、すべての IdP をそれ自身のスコープに縛り、アサーションをクレームに変換する方法。

この側では、authn-bridge は SAML サービスプロバイダーです。フェデレーション (RENATER のFédération Éducation-Recherche、または eduGAIN) に一度登録され、フェデレーションのメタデータを信頼します。メタデータは署名された一つの文書で、すべてのメンバー IdP、その署名鍵、各 IdP が保証してよいドメインを列挙しています。SAML のコードはgo-authn/saml です。

saml {
  key_file  = "/var/lib/authn-bridge/saml.key"   # RSA: IdPs encrypt assertions to it
  cert_file = "/var/lib/authn-bridge/saml.crt"

  metadata_url         = "https://pub.federation.renater.fr/metadata/fer/idps.xml"
  metadata_cert_file   = "/etc/authn-bridge/metadata-signature-2026.pem"
  metadata_fingerprint = "68:2F:20:58:41:9E:D0:79:EB:FE:3C:27:D6:A4:A4:09:39:6F:AE:3F:10:5F:22:EA:04:0F:04:F3:78:2D:5C:C0"

  discovery = "https://discovery.renater.fr/renater"   # or leave it out for this provider's own list
  # idps    = ["https://idp.univ-example.example/idp/shibboleth"]   # restrict; one entry skips the choice

  names             = { fr = "Passerelle OIDC", en = "OIDC gateway" }
  technical_contact = "admin@example.org"
}
キー既定値
entity_id発行者 + /samlフェデレーション内でのこのサービスプロバイダーの名前
key_file、cert_fileSP の RSA 鍵と証明書
metadata_urlhttps://、他のものが保持するコピーなら file://、ループバックに限り http://
metadata_cert_file、metadata_fingerprintフェデレーションの署名証明書とその SHA-256 フィンガープリント。どちらも必須
discoveryこのプロバイダー自身の一覧人々を送り込む外部のディスカバリーサービス
idpsフェデレーションのすべての IdPログインをこれらのエンティティ ID に制限する
names、descriptions、information_url、privacy_statement_url、technical_contact名前としての発行者のホストSP メタデータに入るもの

メタデータの署名者は固定される

メタデータに署名する証明書はこのホスト上のファイルで、その SHA-256 フィンガープリントは設定に書かれています。証明書は起動のたびにフィンガープリントと照合されるので、ディスク上で置き換えられたファイルは信頼されずに検出されます。

authn-bridge: saml: fed/fed.crt is not the certificate with fingerprint 68:2F:20:58:41:9E:D0:79:EB:FE:3C:27:D6:A4:A4:09:39:6F:AE:3F:10:5F:22:EA:04:0F:04:F3:78:2D:5C:C0

保証する対象の文書と同じ経路で届く鍵は、何も保証しません。そのためフィンガープリントはフェデレーションのウェブページから入手し、証明書を運んできたダウンロードからは決して入手しません。

openssl x509 -in /etc/authn-bridge/metadata-signature-2026.pem -noout -fingerprint -sha256

文書が拒否される場合

  • その証明書で署名されていない、SHA-1 で署名されている、または署名がルート以外の要素を対象としている場合

  • validUntil がない、またはそれを過ぎている場合。 これは 2026 年 9 月 29 日に公開されたRENATER 自身のメタデータを、10 月 10 日に読んだものです。

    $ authn-bridge check --config v/renater-expired.hcl
authn-bridge: the federation's metadata: metadata expired at 2026-10-08T07:30:02Z

  • validUntil が 28 日より先の場合: 何年も有効な文書は、リプレイによって何年も生かされ続けかねません

  • 使用中のものより古い場合 (validUntil がより早い)。正しく署名されていて、まだ期限切れでもないので、他に拒否するものがなく、途中にいる誰かが提供する、その後に失効した鍵を持つものかもしれません

  • ループバック以外への平文の http の場合。署名は変更を検出しますが、新しい文書を止めて古いものを提供し続けるプロキシは検出できません

メタデータの更新

メタデータはプロバイダーが待ち受けを始める前に取得され、その後は文書の cacheDuration の四分の三の時点で再度取得されます。五分より早くも、十二時間より遅くもならず、管理 API のRefreshMetadata が求めたときにも取得されます。失敗した更新は最後の正常なコピーを保持しますが、そのコピー自身の validUntil までに限ります。それを過ぎると何も保証されず、すべての IdP が消え、/readyz はプロバイダーが ready でないと述べます。フェデレーションのサーバーに短時間届かないだけなら誰もログアウトされませんが、何日も届かない場合に、プロバイダーが古い鍵を信頼し続けることはありません。

文書内では、IdP は SAML 2.0 を話し、HTTP-Redirect の SingleSignOnService を公開している場合にのみ保持されます。二度記述されたエンティティは、どちらの記述が正しいか分からないので、完全に除外されます。あるメンバーの読めない証明書は、フェデレーションではなくそのメンバーだけを除外します。

各 IdP が述べてよいこと

フェデレーションには数百のメンバーがいて、そのどれもが、そうでなければ自分はalice@another-university.example だと述べることができてしまいます。すべてのメンバーのメタデータは、保証してよいドメインである shibmd:Scope を列挙しており、正規表現のスコープは尊重されずに無視されます。

識別子。 スコープ付きの値 (subject-id、pairwise-id、eduPersonPrincipalName、eduPersonScopedAffiliation) が、表明している IdP のスコープの外にあれば破棄され、@ が二つ以上ある値はどのスコープにも属しません。

グループ。 ログインを許された IdP が複数ある場合、eduPersonEntitlement またはisMemberOf の値は、その名前空間がその IdP のスコープのいずれか、またはその配下にある場合にのみ保持されます。

値その名前空間
urn:mace:<domain>:...<domain>
urn:geant:<domain>:... (AARC-G002)<domain>
https://<host>/...<host>
それ以外なし: 破棄

グループは、すべてのリソースサーバーとすべての証明書で、人が何をしてよいかを決めるので、誰も位置づけられない値は渡されません。多くの機関の人々のグループを表明するコミュニティプロキシは、エンティティ ID で明示的に指名され、表明してよいプレフィックスも指定されます。

claims {
  trusted_groups = {
    "https://proxy.eduteams.org/saml2/idp/metadata.php" = ["urn:geant:eduteams.org:"]
  }
}

saml { idps } にちょうど一つの IdP がある場合は、その IdP がすべての値について信頼されます。

アサーションからクレームへ 

claims {
  username = "eppn"            # preferred_username: eppn, subject_id, uid or mail
  groups   = ["entitlement"]   # groups: entitlement, scoped_affiliation, affiliation, is_member_of
}

uid と mail はどのスコープにも縛られず、affiliation (staff、student) はどの機関も指しません。そのためどれも、saml { idps } にちょうど一つの IdP が列挙されている必要があり、複数ある場合は起動時に拒否されます。

sub。 その元になる識別子は、subject-id、pairwise-id、eduPersonPrincipalName、eduPersonTargetedID、そして修飾子が IdP 自身である永続的な NameID の順で採用されます。IdP のエンティティ ID で修飾され、sub はそれをサブジェクトソルトの下で HMAC-SHA256 にしたものです。安定していて、元に戻せず、アドレスではありません。public はすべてのクライアントで同じで、pairwise はクライアントごとに異なります。これらのどれも出さない IdP は、誰も二度認識できなくなるので拒否されます。メールは決して識別子になりません。email_verified もありません。IdP がアドレスを表明しても、その人がそれを読めると誰かが確認したことにはならないからです。

リクエストが IdP に求めること。 prompt=none は IsPassive になり、セッションのない IdP はlogin_required を返します。prompt=login と max_age=0 は ForceAuthn になります。それ以外のmax_age では、IdP がそれより前に認証した人は ForceAuthn 付きで送り返されます。acr_values はRequestedAuthnContext になり、別のコンテキストで応答する IdP は拒否されます。第二要素を求めたクライアントが、実際にはそうでないのに得たと告げられることは決してありません。

拒否されるもの

ACS では、go-authn/saml が拒否するすべてです。署名のない、または SHA-1 のアサーション、複数のアサーション、リプレイされたもの、他のスコープの識別子。そしてこのプロバイダー自身の拒否が続きます。

  • 別のブラウザーに届けられた IdP の応答: ログインは、応答が運ぶ RelayState ではなく、その人自身の封印されたクッキーを通じて見つけられます。そうでなければ、誰でも自分の IdP の応答を他人のブラウザーに送り、送信者の ID でその人をログインさせられてしまいます
  • 設定がもう許可していない、または管理 API が無効化した IdP
  • ここで無効化された人や機関。その機関が何と言おうと

起動時には、すべてを列挙して制限できない RENATER のディスカバリーサービスと IdP のリストを併用している場合に:

authn-bridge: saml: an external discovery service lists every IdP; with `idps` restricted, leave `discovery` out and this provider lists them itself
